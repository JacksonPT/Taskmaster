## Why

Taskmaster has been built through eleven learning modules, but its project-local OpenSpec baseline is empty, so completed behavior, security guarantees, AI boundaries, and the remaining module order are not captured as durable project contracts. Establishing that source of truth now prevents future modules from drifting and makes the collapsible daily-plan sidebar the next clearly bounded learning change.

## What Changes

- Establish `Taskmaster/openspec/` as the canonical, tracked specification root and configure it with the project's stack, architecture, teaching style, verification standards, and one-question-at-a-time apply workflow.
- Document Modules 1-11 as baseline capabilities derived from the current code, README, schema, and Git history.
- Replace the legacy sidebar-only proposal with Module 11.1 inside this project-wide change: a responsive, collapsible daily-plan sidebar that keeps the main summary, hides item-level rationale, and preserves manual ordering.
- Define an ordered learning roadmap for Modules 12-16: completion encouragement, task notes/resources, progress dashboard, quality hardening, and deployment/portfolio readiness.
- Require future work to proceed one module at a time through its own OpenSpec change, with focused user questions, top-down learning comments, verification, reading order, and reusable lessons.
- Remove the ignored legacy `Taskmaster/specs/` planning root after the canonical OpenSpec artifacts are complete and validated.

## Capabilities

### New Capabilities
- `project-foundation`: Module 1 product identity, supported stack, development workflow, and learning-project conventions.
- `public-landing-page`: Module 2 responsive product presentation and session-aware entry into Taskmaster.
- `task-management`: Modules 3, 4, and 6 task workspace, validation, lifecycle interactions, and durable task behavior.
- `database-persistence`: Module 5 Prisma/PostgreSQL architecture, migrations, and generated-client expectations.
- `user-authentication`: Module 7 Clerk sign-in, session handling, protected route, and authenticated Server Action behavior.
- `private-task-ownership`: Module 8 ownership derivation and user-scoped isolation for every private task operation.
- `ai-priority-suggestions`: Module 9 structured per-task priority recommendations, rationale, override, and persistence behavior.
- `ai-completion-plans`: Module 10 structured task action plans, eligibility, regeneration, persistence, and stale-write protection.
- `daily-planning`: Module 11 batch task ordering, semantic AI validation, current-plan persistence, quota leases, manual reordering, and focus integration.
- `daily-plan-sidebar`: Module 11.1 responsive sidebar placement, true collapse behavior, compact task rows, and preserved reorder controls.
- `project-learning-roadmap`: Beginning-to-end module ordering, future Modules 12-16, one-module-at-a-time delivery, teaching comments, user checkpoints, and completion summaries.

### Modified Capabilities

None. The project-local baseline is currently empty.

## Impact

- Adds and configures the canonical `openspec/` and OpenCode command/skill integration generated by `openspec init`.
- Adds baseline and roadmap specifications under this change for later synchronization into `openspec/specs/`.
- Targets `components/tasks/daily-plan-panel.tsx`, `components/tasks/task-dashboard.tsx`, and `README.md` for the next sidebar implementation module.
- Updates repository specification tracking by replacing the ignored legacy `/specs` layout.
- Does not change Prisma models, Gemini prompts, AI quota enforcement, Clerk authorization, or task data during the sidebar module.
